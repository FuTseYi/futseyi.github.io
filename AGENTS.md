# FuTseYi website — AI maintenance rules

The goal is a **small, durable, professional academic homepage**. Avoid adding a framework or complex infrastructure.

- Public identity: **FuTseYi / Shine**. Do not use FuXieyi or copy other researchers' credentials.
- Homepage: `index.html` (semantic HTML). All homepage-local assets use relative paths so the file can be opened directly on Windows/macOS. The homepage Writing links point to the live blog because it is generated by CI. Small progressive-enhancement navigation script: `assets/site.js`.
- CSS: `assets/style.css`, shared by the homepage and Writing.
- Articles: `posts/*.md`, with title, date, description and optional comma-separated tags; optional `draft: true`.
- Publish: `.github/scripts/build.py` (Python-Markdown), `.github/workflows/deploy.yml` (GitHub Pages).
- Generated HTML: `blog/` is ignored and regenerated from `posts/` during deployment; never commit generated HTML.
- Keep the design understated, readable, accessible, and responsive. The header uses a sticky navigation and accessible mobile menu; on the homepage a wide-screen directory tracks section state. Preserve keyboard Escape handling, `aria-expanded`, `aria-current`, and no-JavaScript fallback.
- NEVER publish private contact details, unsupported achievements, or inferred publications/jobs. Use only the public email: hello@futseyi.com.
- **Important GitHub writes:** when creating a Git tree via the API, ALWAYS specify the current commit's `base_tree_sha`. Without it, unrelated files/directories may disappear. Verify the full tree after updating the branch.
- Homepage-only preview: open `index.html` directly, without Python or a local HTTP server. For full Writing/build changes, reproduce CI: install `Markdown>=3.7,<4`, run `python .github/scripts/build.py`, stage the output as the workflow does, and run `python .github/scripts/verify.py`. The generator validates post metadata before replacing old generated files; a clean rebuild removes pages for deleted posts. Broken local images/links should fail verification.
- When adding a post, edit `posts/*.md`; the build will regenerate `blog/index.html` and article pages automatically.
- Do not migrate old `My-Website` content without reviewing privacy, image paths and URL preservation.

- Homepage Writing section links to the blog index intentionally; do not hardcode the latest article in the homepage.
- Images for Markdown articles belong in `assets/images/` with root-absolute paths. Keep alt text and use optimized image files.

- Profile README: `.github/scripts/sync_readme.py` derives `README.md` from the homepage hero (name, `.bio`, `.profile-note`, `.profile-languages`, `.profile-motto`, mailto/canonical URL) and non-draft `posts/*.md`. Personal details and mottos belong in `index.html`, never duplicated as hardcoded text in the generator. The site deploy injects a matching Latest Posts list into the published homepage; the source HTML stays directly previewable. The two repository READMEs must be byte-for-byte identical; never manually edit a generated README. GitHub Actions pushes a changed README locally; remote updates require `PROFILE_README_TOKEN` secret scoped only to `FuTseYi/FuTseYi` Contents write.
