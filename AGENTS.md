# FuTseYi website — AI maintenance rules

The goal is a **small, durable, professional academic homepage**. Avoid adding a framework or complex infrastructure.

- Assets are grouped into `assets/css/`, `assets/js/`, `assets/icons/`, and `assets/images/{profile,education,community}/`. Keep existing filenames and update generated README references through the generator when moving images.

- Public identity: **FuTseYi / Shine**. Do not use FuXieyi or copy other researchers' credentials.
- Homepage: `index.html` (semantic HTML). All homepage-local assets use relative paths so the file can be opened directly on Windows/macOS. The homepage Blog links point to the live blog because it is generated by CI. Small progressive-enhancement navigation script: `assets/js/site.js`.
- CSS: `assets/css/style.css`, shared by the homepage and Blog. Blog headers and footers are derived from `index.html` by the existing builder; update the homepage rather than maintaining a separate copy. Blog navigation marks Blog active, and its shared footer returns to the current page top.
- Articles: `posts/*/index.md`, with required title and date, and optional comma-separated tags. All files in `posts/` are published on deployment; there is no draft or scheduled-publication switch. Dates only control display and newest-first ordering.
- Publish: `.github/scripts/build.py` (Python-Markdown), `.github/workflows/deploy.yml` (GitHub Pages).
- Generated HTML: `blog/` is ignored and regenerated from `posts/` during deployment; never commit generated HTML.
- Keep the design understated, readable, accessible, and responsive. The header uses a sticky navigation and accessible mobile menu; on the homepage a wide-screen directory tracks section state. Preserve keyboard Escape handling, `aria-expanded`, `aria-current`, and no-JavaScript fallback.
- NEVER publish private contact details, unsupported achievements, or inferred publications/jobs. Use only the public email: hello@futseyi.com.
- **Important GitHub writes:** when creating a Git tree via the API, ALWAYS specify the current commit's `base_tree_sha`. Without it, unrelated files/directories may disappear. Verify the full tree after updating the branch.
- Homepage-only preview: open `index.html` directly, without Python or a local HTTP server. For full Blog/build changes, reproduce CI: install `Markdown>=3.7,<4`, run `python .github/scripts/build.py`, stage the output as the workflow does, and run `python .github/scripts/verify.py`. The generator validates post metadata before replacing old generated files; a clean rebuild removes pages for deleted posts. Broken local images/links should fail verification.
- Cross-platform full local preview: use `preview.py` with Python 3.10+ (see `PREVIEW.md`). It builds and verifies an isolated temporary source copy, then replaces `_site/` under a serving lock; failed builds preserve the last good preview. It converts production navigation links only in the preview copy, disables local browser caching, and serves on loopback. Run one preview per checkout; the port must be free even for `--build-only`. Preview watches source files by default; refresh the browser manually after rebuilding. Missing Markdown is installed automatically into a virtual environment. Use `--build-only` for a one-off build without watching or serving. Production source links stay unchanged. Watcher checks: `python -m unittest discover -s .github/scripts -p test_preview.py -v`.
- When adding a post, edit `posts/*/index.md`; the build will regenerate `blog/index.html` and article pages automatically.
- Do not migrate old `My-Website` content without reviewing privacy, image paths and URL preservation.

- Homepage Blog section links to the blog index intentionally; do not hardcode the latest article in the homepage.
- Article resources belong in `posts/<slug>/assets/`, referenced with relative paths such as `assets/example.webp`. The directory name is the URL slug; the builder copies resources alongside each generated article. Keep alt text and use optimized image files.

- Profile README: `.github/scripts/sync_readme.py` derives About (note, bio/Focus, languages, mottos, profile links and visitor badge), Active In names/links without descriptions, and the latest three published posts without dates from `index.html` and `posts/*/index.md`. Omit the hero name heading and portrait; keep shared About content in README order: Homepage, note, bio, Focus/Lang/Motto, Recent Blog link, profile links and visitor badge, matching the webpage order. Do not add separate Website/Contact sections or hardcoded personal text. Use bold, colon-terminated Focus/Lang/Motto labels in both outputs. The README website/Blog URLs derive from `GITHUB_REPOSITORY` in Actions or the homepage canonical URL locally. Include a brief website link for more information. Both repository READMEs are generated from the same text; never edit them manually. Every push to `main` triggers website deployment and README synchronization. The sync workflow tests content parity before publishing. GitHub Actions commits a changed website README and updates the Profile repository only with `PROFILE_README_TOKEN` scoped to `FuTseYi/FuTseYi` Contents write. The website deployment separately injects latest posts into `_site/index.html`.

- Active In is manually curated in `index.html`; only include user-confirmed organizations and roles. Do not infer job titles or formal affiliations from GitHub membership.
- Recent Open Source Contributions is generated by `.github/scripts/sync_activity.py` into `_site/index.html`. After the normal Blog build/staging and README homepage injection, run `python .github/scripts/sync_activity.py --refresh` to query public activity, then run `verify.py`. Offline behavior is tested with `python -m unittest discover -s .github/scripts -p test_sync_activity.py -v`.
- The Publish website workflow refreshes contributions on every deployment (push, manual dispatch, and days 1 and 15 of each month at 01:17 UTC / 09:17 Asia/Shanghai). No additional personal token is required: Actions uses its read-only `GITHUB_TOKEN` for public metadata.
- Public activity is limited to the API's recent window (currently 30 days / 300 events). Select the user's branch pushes and authored non-draft PR events, deduplicate repositories by latest activity, and retain up to twelve public, non-archived repositories, showing three initially with an accessible expand/collapse control. Stars, watches, other actors, private repositories, and the personal website/profile repositories (`FuTseYi/futseyi.github.io`, `FuTseYi/FuTseYi`) are excluded, including from reused snapshots. This is an activity summary, not a complete contribution history.
- `_site/contributions.json` stores only the displayed public metadata and refresh timestamp. Deployments query GitHub directly; if refresh fails, use the local snapshot or previously deployed JSON, preserving its original timestamp. Without a valid snapshot, keep the source GitHub-activity link. Local preview reuses an existing snapshot and queries GitHub only when none is available. No Actions cache or time-based expiration is used. Do not commit generated snapshots, mock articles, or `_site/` content. Direct-file preview shows the static activity link; full local preview requires the staged build.
